# 订单字段核验与提交前差异核对

状态：TASK-043 的工作样例。它使用内置虚构订单，不需要后端写入、模型或外网；正式任务入口和
TASK-027 的辅助命令尚未接入。

## 样例

`frontend/src/order-practice.js` 内置两张虚构资料：

- **客户确认单**：蓝色收纳盒，数量 3 件，单价 28 元，确认金额 84 元；
- **待核验订单**：同一商品，数量 2 件，金额 56 元，等待核对。

打开「订单核验练习」并选择「待核验订单.md」后，详情区显示可读屏的字段核验面板。

## 交互

1. 面板左侧列出客户确认单的商品、数量、单价、金额和来源版本。
2. 右侧提供“核对后数量”“核对后金额”输入；初始值来自待核验订单。
3. 点击“提交核验”前会校验：
   - 数量必须是正整数；
   - 金额必须是正数；
   - 数量和金额必须改成来源确认值；
   - 金额与数量、单价不一致时拒绝。
4. 点击“取消核验”只显示取消状态，不产生提交结果。
5. 来源版本比本次核对版本新时，提交被阻止并显示“来源有更新，需复核”；点击“采用最新来源并复核”后才可重新提交。
6. 同一结果重复点击“提交核验”只保留一条结果，并提示不会产生第二次提交。

面板使用真实表单标签、`role="alert"` 错误、`role="status"` 状态和可聚焦标题；没有自动焦点跳转或只靠颜色表达状态。键盘可以打开练习、填写字段、取消或提交。

## 数据与网络

- 提交是**本地演示状态**，不调用写入 API，不产生 POST，不保存真实订单。
- 订单和确认单都是合成数据；页面刷新后草稿由项目库的 localStorage 恢复。
- 没有网络请求、模型调用、真实用户资料或真实金额。
- 这不等于已经接入通用任务状态、TASK-027 辅助命令或正式业务提交；这些留给后续任务。
