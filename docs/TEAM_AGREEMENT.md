## 二、任务、决定与验收

按 [贡献指南](../CONTRIBUTING.md) 工作。Issue 明确负责人、范围、交付、验收人、日期、依赖；新增范围先协商。技术分歧记录方案、证据和影响，由维护者作仓库技术决定；影响署名、费用和分配的决定由受影响成员明确书面确认。

验收依据是约定功能、测试、兼容性、来源授权和文档；反馈应具体可验证。合并 PR 不确认未记录的经济承诺。每周简短同步进度，频率可协商；志愿成员不承担未约定的最低工时或随时响应义务。

1. 保留原作者、原团队、上游来源和已有许可；不得将他人成果列为个人原创。

3. 已合法授予的开源权利不因成员退出或以后商业化而简单撤回。具体条件和终止情形以许可证为准。
4. 本协议不重新许可无权处分的上游代码、商标、SDK、模型和数据。第三方材料逐项核实来源和许可。
5. 公开仓库不接收需要保密的交付；确有需要时另定私密载体、权限、授权与保密期限。
6. 以后商业化、申请专利、闭源授权或转让成果，应核对现有许可和第三方权利，需要时取得相关权利人单独授权；维护者不能代他人处分权利。

## 四、贡献与署名

在 Issue／PR 记录参与者、工作、交付与证据，共同开发保留作者和 `Co-authored-by`。代码、设计、文档、测试、评测、部署和审查都计入贡献，不单按提交数、代码行或工时排名。

每次成果提交或对外发布前，填写成果确认单：

```text
成果名称／版本／提交 SHA：
用途（验收／论文／演示／商业交付）：
原团队、上游和第三方材料及授权依据：
逐人贡献与 Issue／PR／交付证据：
参与名单与资格核验：
署名名单、顺序、身份及理由：
其他贡献者致谢方式（公开个人信息需本人同意）：
各受影响成员确认记录与日期：
```

代码署名、验收参与和论文作者顺序分别确认。维护仓库、拉人或拥有账号不自动取得第一署名；贡献代码不自动保证名额或论文作者资格。争议未解决的署名或成果不得擅自以成员名义提交，结合官方截止和撤回规则协商处理。

## 五、报酬、奖金、费用与商业收益

下列事项分别确认，不默认均分，不用“以后再说”替代已经承诺的有偿条件：

```text
是否有偿；付款方／收款方：
里程碑、交付、验收、金额、付款期限和税费：
是否有奖金；获奖与收款主体：
可分配奖金基数（税费、允许扣除成本及凭证）：
参与分配者及各自比例／金额、计算公式（比例合计 100%）：
结算期限及向成员提供明细、凭证的方式：

未获奖／项目终止时已验收工作、已批准费用的结算：
退出成员已完成贡献对应的报酬／奖金处理：
商业收益范围、成本、分配、查账和期限（无安排写“未约定”）：
各受影响成员确认记录与日期：
```

未确认分配不产生默认比例，不影响此前有效约定或依法应享权益。未经批准的支出不能自行要求全体分摊；已批准费用依约结算。股权需要独立主体和签署文件，本协议不承诺股权。

## 六、安全与沟通

不共享 GitHub 密码，不公开密钥、真实用户资料或未授权数据。群聊用于协调，影响任务或权益的结论保存可追溯记录；个人与财务确认材料仅向必要成员开放。安全问题按 [安全指南](../SECURITY.md) 处理。

## 七、退出和交接

成员可以退出，建议提前七日通知；紧急情况及时沟通。交接任务状态、分支、未完成内容、运行方法和风险。维护者撤销不再需要的权限并轮换相关凭据。退出不删除真实贡献和有效署名，不自动免除结算，也不撤回已生效的开源许可。

严重违规需限制访问时，记录事实、范围和通知，允许补充证据或申诉；不通过删除贡献历史惩罚成员。
