# 字幕纠错到业务确认

状态：TASK-044 的文本回退样例。它不重复实现 TASK-028 的离线 ASR/TTS，而是把“转写可能有错、
业务字段必须由本人确认后才改变”的交互单独落地。

## 样例

打开「订单核验练习」并选择「待核验订单.md」，详情区会出现字幕纠错面板：

- 原转写：`客户要蓝色收纳袋两件，单价二十八元。`
- 确认单：`蓝色收纳盒`，`3 件`，单价 28 元
- 当前业务字段：`蓝色收纳袋`，`2 件`，28 元
- 更正输入：商品 `蓝色收纳盒`，数量 `3`

原转写、业务原值和更正内容同时可见；更正记录保留字段的旧值/新值。

## 确认规则

1. 在点击“确认更正并写入业务字段”之前，业务字段始终保持原值。
2. 点击“取消”只提示未应用，业务字段不变。
3. 点击确认后，才把商品和数量写入业务状态，并追加一条更正记录。
4. 没有待应用的更正时，确认不会伪造一次变更。
5. “无麦克风？切换到文字输入”会显示可编辑文字转写；没有请求麦克风权限。
6. 页面不调用写入 API，不产生 POST，不创建真实订单。

## 音频授权与保留

- 当前样例没有录音功能，也没有请求麦克风权限。
- 当前不产生、不上传、不保存音频；只保留合成文字和本地页面状态。
- 未来接入 TASK-028 时，录音必须在用户明确同意后才开始；原始音频默认不落盘，
  transcript 与业务字段分开授权，删除流程必须同时清除音频、转写和派生的模型上下文。
- 此设计没有被当作真实麦克风或真实 ASR 验收。
