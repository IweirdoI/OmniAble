# 备货模拟、缺货接管与设备验收契约

状态：TASK-046 / [Issue #66](https://github.com/IweirdoI/OmniAble/issues/66) 的设计 + 模拟实现。本文交付物料清单流程、模拟设备原型（`frontend/src/stock-simulation.js`）与**真机准入契约**（第 2 节）；真机部分按契约另行评估，模拟结果不计作真机成功。关联：[远程接待与现场设备协作设计](REMOTE_RECEPTION.md)（共用的控制权/断联/幂等词汇）、[团队岗位资料共享、版本与撤销访问设计](TEAM_KB_ACCESS.md)。

## 1 目标与范围

覆盖验收句：**模拟订单含一次缺货，停止后可由工作人员选择替代材料并再次确认；断联、超时或未确认均停在可识别状态，重试不重复执行；模拟和真机分别报告。**

流程：获确认的定制订单 → 生成物料清单（料箱位、数量）→ 模拟设备逐项取放 → 注入一次缺货 → 停在 `awaiting_decision` → 工作人员两步接管（选择替代 + 再次确认）→ 替换写入清单并留痕 → 从断点继续（已完成物料不重复执行）→ 完成。

不做的事：真机与真实库存系统接入；UI 接线（独立后续任务，避免与进行中的前端工作冲突）；语音（TASK-028）；多缺货并发（原型单缺货决定卡）。

## 2 设备验收契约（真机评估的准入条件）

真机接入评估时逐条核对，任何一条不满足即不通过：

1. **动作白名单**：设备只接受预设轻小物品取放任务；每个取放有唯一步骤记录（sku、数量、料箱位）。
2. **期望状态版本（CAS）**：设备状态版本单调递增；变更操作携带期望版本，不匹配即拒绝且不变更（对齐 `src/agent/workspace.py:36-42` 乐观锁、`src/agent/service.py:523-532` 批准后复核）。
3. **可停止**：工作人员随时停止，停在可识别状态；已完成步骤保留，恢复跳过（对齐 `src/agent/run_store.py:265-288` 已确认步骤语义）。
4. **接管边界**：缺货替代由人决定，"选择 + 确认"两步；Agent 无权代替人对缺货做任何决定，设备永不自动替代。
5. **幂等重试**：重复启动、重复确认、终态后再执行均返回首次结果，不产生第二次变更。
6. **结果反馈**：每步返回结构化结果（取出 / 缺货 / 决定卡）；日志只留最小结果（类别、摘要、时间）。
7. **断联**：Agent 链路丢失只冻结 Agent 侧，本地人员操作不受限；心跳超时自动判定；恢复后从断点继续，不自动重发。
8. **报告分离**：模拟结果与真机结果分别报告，不将模拟计作真机成功（验收原文）。

## 3 状态机

设备状态：`idle → running →（缺货）awaiting_decision →（确认）running → completed`；旁路 `stopped`（人工停止，可恢复）、`cancelled`（终态）。两个正交标记：

- `agentLinkLost`：只冻结 Agent 侧（远程驱动被拒）；本地工作人员的观察、替代、停止、恢复不受限。
- `decisionTimedOut`：缺货决定超时只做标记，**永不自动选择替代材料**；事后人工确认仍有效。

替换留痕：确认后原物料标记被替代，清单写入替代 SKU 并携带 `substitutedFor`，最终报告可追溯。

## 5 原型与测试

- `frontend/src/stock-simulation.js`：纯逻辑状态机，无 vue 依赖、不接 UI、不接真机。虚构订单与库存全部合成数据；替代清单本身可含库存为 0 的项（检验"替代也不足"的拒绝路径）。
- `frontend/tests/stock-simulation.test.js`：10 条 node --test，覆盖第 6 节 S1–S9。
- UI 接线为独立后续任务；届时按 [ORDER_VERIFICATION.md](ORDER_VERIFICATION.md) 的无障碍模式（真实表单标签、`role="status"`/`role="alert"`、键盘全流程）补浏览器回归。

## 6 验收样例

标注：〔本地〕`node --test` 已覆盖；〔真机〕按第 2 节契约另行评估。

- **S1 物料清单生成**〔本地〕：数量、料箱位正确；非法数量被拒。
- **S2 无缺货完整备货**〔本地〕：逐项取出、库存扣减、最后一件原子完成；终态后重复执行被拒。
- **S3 缺货停在可识别状态**〔本地〕：转入 `awaiting_decision`，决定卡含缺口数量、当前库存与预设替代；已完成物料保留。
- **S4 人工替代接管**〔本地〕：Agent 决定被拒；未知替代被拒；替代库存不足被拒；选择 + 确认后替换留痕，断点续跑到完成。
- **S5 幂等**〔本地〕：重复启动返回首次运行；重复确认返回首次结果；终态后不再执行。
- **S6 过期状态版本**〔本地〕：CAS 拒绝且设备无变化。
- **S7 断联**〔本地〕：显式断开与心跳超时都冻结 Agent 侧；工作人员在断联期间可完成替代确认；重连后从断点继续，已完成物料不重复取。
- **S8 未确认超时**〔本地〕：只标记超时，不自动替代；人工确认仍然有效，流程不卡死。
- **S9 停止与恢复**〔本地〕：停止停在可识别状态；恢复跳过已完成物料；重复停止被拒；取消为终态。
- **S10 真机验收**〔真机〕：按第 2 节契约逐条评估，另行报告，不计入本任务。

## 7 边界与未决事项

- 库存是模拟静态表；真机接入时库存来源、替代材料的审批层级与多缺货并发处理需按真机契约评审。
- 原型由显式调用驱动（确定性、可测）；真机的实际驱动节奏、超时与重试策略接入运行记录后另行定义。
- Agent 远端驱动备货设备时，按 [REMOTE_RECEPTION.md](REMOTE_RECEPTION.md) 的观察/控制权限分离接入，本文契约与其设备动作确认链一致。
